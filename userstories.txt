Here's a set of user stories for the Shellforge MVP, organized by epic and prioritized using MoSCoW (Must/Should/Could/Won't).

---

## Epic 1: First Launch & Onboarding

### US-1.1 — Install and Launch (MUST)
**As a** CS student,
**I want to** install Shellforge with a single command and launch it,
**so that** I can start learning without setup friction.

**Acceptance Criteria:**
- `curl -fsSL https://shellforge.dev | sh` installs a single binary to `/usr/local/bin`
- `shellforge` launches the TUI within 2 seconds
- If a previous session exists, offer to resume or start fresh
- If no terminal supports PTY, show a clear error message

---

### US-1.2 — Understand the Interface (MUST)
**As a** first-time user,
**I want to** see a clear split-pane layout with lesson instructions on top and a working shell below,
**so that** I know where to read and where to type.

**Acceptance Criteria:**
- Top pane shows: lesson title, objective, hints
- Bottom pane shows: an interactive shell prompt (bash/zsh)
- A visual divider clearly separates the panes
- Status bar shows: current lesson, module, and progress
- First-time hint: "Type commands below, just like a normal terminal"

---

### US-1.3 — Skip or Exit Anytime (MUST)
**As a** user,
**I want to** exit Shellforge cleanly at any time,
**so that** my host machine is left untouched.

**Acceptance Criteria:**
- `Ctrl+Q` or `Esc` twice exits the program
- Sandbox directory `/tmp/shellforge/<session-id>/` is deleted on exit
- Terminal is restored to its original state (no raw mode stuck)
- No orphan processes remain

---

## Epic 2: Core Learning Loop

### US-2.1 — Read a Mission (MUST)
**As a** learner,
**I want to** read the mission objective and hints for the current lesson,
**so that** I understand what I'm supposed to accomplish.

**Acceptance Criteria:**
- Lesson displays title, objective, background, and 2–3 hints
- Hints are collapsible (press `?` to reveal)
- Text wraps correctly in terminal
- Long lessons are scrollable (arrow keys or `j`/`k`)

---

### US-2.2 — Execute Real Commands (MUST)
**As a** learner,
**I want to** type real shell commands in the sandbox,
**so that** I gain muscle memory for actual Unix workflows.

**Acceptance Criteria:**
- All commands run in a real subshell (bash or zsh)
- Sandbox has all files specified by the lesson's setup script
- `Ctrl+C` cancels the running command (not the tutor)
- `Ctrl+L` clears the screen
- Command history works (up arrow)
- `pwd` shows the sandbox path, not the user's real home

---

### US-2.3 — See Live Assertion Feedback (MUST)
**As a** learner,
**I want to** see which objectives I've completed in real time,
**so that** I know when I've solved the mission.

**Acceptance Criteria:**
- After each command completes, assertions are re-evaluated
- Checklist shows: `[ ]` pending, `[✓]` passed, `[✗]` failed
- Passing all assertions triggers a success notification
- Assertions never block the shell (run async)

---

### US-2.4 — Recover from Mistakes (MUST)
**As a** learner,
**I want to** reset the sandbox to its initial state,
**so that** I can retry without restarting the program.

**Acceptance Criteria:**
- `Ctrl+R` (or a command) resets the current lesson
- Sandbox is torn down and recreated from the YAML setup
- Assertion checklist resets to all pending
- A confirmation prompt prevents accidental resets

---

## Epic 3: Progression & Completion

### US-3.1 — Complete a Lesson (MUST)
**As a** learner,
**I want to** be recognized when I've solved a mission,
**so that** I feel a sense of accomplishment.

**Acceptance Criteria:**
- All assertions pass → success message appears
- A subtle celebratory cue plays (e.g., colored banner, no sound required)
- Prompt: "Press Enter to continue to next lesson"
- Progress is saved to `~/.config/shellforge/progress.json`

---

### US-3.2 — Progress Through Modules (MUST)
**As a** learner,
**I want to** move to the next lesson after completing the current one,
**so that** I build skills incrementally.

**Acceptance Criteria:**
- Next lesson loads automatically after success
- Sandbox is torn down and recreated for the new lesson
- Module 01 lessons are unlocked by default
- Later modules unlock after completing the previous module

---

### US-3.3 — See Overall Progress (SHOULD)
**As a** learner,
**I want to** see my overall progress across modules,
**so that** I know how far I've come.

**Acceptance Criteria:**
- Status bar shows: `Module 02 • Lesson 3/5 • 12/30 total`
- A progress menu (`Ctrl+P`) shows all modules and completion state
- Completed lessons are checkmarked

---

## Epic 4: Sandbox & Safety

### US-4.1 — Trust the Sandbox (MUST)
**As a** cautious user,
**I want to** be confident that my real filesystem is safe,
**so that** I can experiment freely.

**Acceptance Criteria:**
- Sandbox is created at `/tmp/shellforge/<uuid>/sandbox`
- Shell starts with `cwd` set to the sandbox
- `$HOME` is remapped to the sandbox (or a subdir)
- `rm -rf ~/*` inside sandbox does NOT touch the real home
- Any files the setup script needs (dotfiles, etc.) are mocked

---

### US-4.2 — Clean Up After Exit (MUST)
**As a** user,
**I want to** know that Shellforge leaves no residue,
**so that** my machine stays clean.

**Acceptance Criteria:**
- On clean exit: sandbox directory is removed
- On crash (SIGKILL): a stale session marker lets next launch clean up
- No background processes spawned by lessons survive exit
- `~/.config/shellforge/` only contains progress.json (opt-in)

---

## Epic 5: Content & Lesson Authoring

### US-5.1 — Load Lessons from YAML (MUST)
**As a** Shellforge developer,
**I want to** define lessons in YAML,
**so that** I can add content without recompiling.

**Acceptance Criteria:**
- Lessons are embedded via `go:embed`
- Schema supports: id, title, description, hints, setup, assertions, success_message
- Invalid YAML produces a clear error at build/load time
- One YAML file per lesson under `/lessons/`

---

### US-5.2 — Assert Filesystem State (MUST)
**As a** lesson author,
**I want to** assert on files, directories, content, and permissions,
**so that** I can verify any Unix task.

**Acceptance Criteria:**
- Supported assertion types:
  - `file_exists`, `directory_exists`, `file_absent`
  - `file_content_contains`, `file_content_regex`
  - `file_permissions` (octal)
  - `command_exit_code` (run a command, check exit code)
- Assertions are re-evaluated after each shell command
- Failed assertions show a helpful diagnostic (why it failed)

---

### US-5.3 — Ship Starter Curriculum (MUST)
**As a** new user,
**I want** at least 6 lessons across 6 modules available on install,
**so that** I have a complete learning arc.

**Acceptance Criteria:**
- One lesson per module (minimum) for MVP
- Each lesson has: setup, objective, 2+ hints, 2+ assertions
- All lessons tested on macOS + Linux
- Lessons are progressively harder

---

## Epic 6: Signals & Terminal Correctness

### US-6.1 — Handle Ctrl+C Correctly (MUST)
**As a** learner running a long command,
**I want** `Ctrl+C` to cancel the command, not the tutor,
**so that** I can recover from mistakes.

**Acceptance Criteria:**
- `Ctrl+C` sends SIGINT to the PTY's foreground process
- Shellforge itself is unaffected
- Prompt returns within 100ms

---

### US-6.2 — Handle Window Resize (MUST)
**As a** user,
**I want** the UI to reflow when I resize my terminal,
**so that** the layout stays usable.

**Acceptance Criteria:**
- SIGWINCH updates both panes' dimensions
- PTY is resized via `pty.Setsize()`
- No visual artifacts (e.g., stale content) after resize

---

### US-6.3 — Suspend and Resume (SHOULD)
**As a** user,
**I want** `Ctrl+Z` to suspend Shellforge like any terminal app,
**so that** I can drop to my host shell if needed.

**Acceptance Criteria:**
- SIGTSTP suspends Shellforge cleanly
- `fg` resumes with state intact (PTY, viewport, progress)
- No orphan child processes while suspended

---

## Epic 7: Polish & Distribution

### US-7.1 — Install via Homebrew (SHOULD)
**As a** macOS user,
**I want** to install Shellforge with `brew install`,
**so that** updates are easy.

**Acceptance Criteria:**
- `brew install shellforge/tap/shellforge` works
- Formula is auto-updated on release
- `shellforge --version` reports the correct version

---

### US-7.2 — Cross-Platform Binary (MUST)
**As a** Linux or macOS user,
**I want** a prebuilt binary,
**so that** I don't need Go installed.

**Acceptance Criteria:**
- GitHub Releases has: `darwin-arm64`, `darwin-amd64`, `linux-amd64`, `linux-arm64`
- Install script auto-detects platform
- Binary is < 20MB
- `go install github.com/shellforge/shellforge@latest` also works
